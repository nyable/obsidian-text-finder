## 文档分工

- README 回答用户“有什么功能、如何使用、有哪些限制”。
- 长期知识按功能、交互、视觉、架构、兼容性和陷阱分工；开发与测试文档提供操作方法。每类事实有主要归属，其他文档优先链接而非重复定义。
- 源码事实、已批准但存在实现差异的约束、合理推断和实机待验证项必须区分；变化时与对应代码一起更新。
- `tests/` 保留可执行测试、诊断脚本与测试样例，不承载开发说明文档。
- API 形状检查和自动测试通过不等于真实应用验收通过；未验证的平台应明确标注。
- 临时计划、任务清单和进度留在 OpenCode 会话及其任务管理中，不写入上述长期知识。
